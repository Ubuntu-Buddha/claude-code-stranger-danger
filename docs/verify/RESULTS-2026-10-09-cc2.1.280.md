## Findings

- **F1 — group-writable gate config. A bug, and also a positive result.**
  - **First attempt:** the config was `-rw-rw-r--` in a `drwxrwxr-x` folder (Ubuntu umask 002, user-private group). Every gate call in rows 1, 5, 9, 11, 22 and 26 failed closed with "config file … is writable by other users". That covered both gates, the main session and subagents, so fail-closed works.
  - **The out-of-box bug:** `setup.py`'s step 3 already does `chmod 700`/`600`, but VERIFY step 2 and `docs/verify/setup.sh` ("merge the snippet into your gate config") don't. Following them with a default umask leaves every gate blocking everything.
  - **Not logged:** these config-problem denies were not written to `decisions.jsonl`.
  - **Fix:** the author set the folder to 700 and the file to 600 before the full run.
- **F2 — VERIFY isolation: the profile isn't empty.**
  - Because `~/sd-verify/project` is under `~`, Claude Code loads `~/.claude/CLAUDE.md` as an ancestor `.claude/CLAUDE.md` even with `CLAUDE_CONFIG_DIR` set. Its `@~/.claude/stranger-danger/RULES.md` import is skipped (an external import never approved in the new profile), so there's no canary.
  - The account's claude.ai connectors also attach through the login.
  - Fix: use a scratch base outside `~`.
- **F3 — on 2.1.280 main sessions have no Glob or Grep tools.**
  - The main-session tool list includes Bash, Read, ToolSearch, WebFetch and WebSearch, and no Glob or Grep. Subagents that list them, such as the quarantine-reviewer in row 17, still get them.
  - So rows 15 and 21 can't run as written.
  - The reader gate's Grep and Glob checks only ever apply in subagents. Main-session searching goes through Bash, which the reader gate doesn't see (already a README limit, but now it covers every main-session search).
  - That makes the sandbox (doctor's "sandbox off" WARN) the control that matters for the main session.
- **F4 — row 7 isn't an end-to-end gate test.** The web-researcher's own instructions refuse local addresses before the gate is consulted. Defence in depth holds, and row 3 shows the gate's host check. Rephrase the row, or accept "deny: agent or gate".
- **F5 — row 24 headless artifact.** With `-p`, the allow rule `Bash(echo test | sh)` doesn't cover the compound command, so Claude Code asks for `sh` and denies it. The gate itself allowed it. An interactive run would show a prompt.
- **F6 — doctor and setup ignore `CLAUDE_CONFIG_DIR` for settings and rules.**
  - `doctor.py` reads `~/.claude/settings.json` (line 197) and `~/.claude/CLAUDE.md` (line 330) whatever the active profile. It passes `config_dir` only to the self-test (line 126). (Pre-release line numbers.)
  - In this profile it reported "rules import PASS / canary set" while the session had no canary. The deny-rule and sandbox WARNs describe the default profile.
  - `setup.py` prints commands that target `~/.claude` as well.
- **F7 — the auto-mode classifier blocked one variant.** A rerun of row 28 with `--setting-sources user` (to suppress F2) was refused, with no reason given. Under rule 7 it was not retried another way.
