**Row 36's first call is a stricter refusal, not a leak.** When a Glob's folder holds `[` or `]`, the gate also judges folder and pattern joined as one pattern, in case a Claude Code version reads them that way. Read as a pattern, `[q]uarantine` matches `quarantine`, so the gate refuses. Claude Code 2.1.295 takes the folder literally, so the call would have found nothing. The refusal is kept. VERIFY row 36 now expects this deny, or "allowed, folder doesn't exist" if the guard is ever dropped. A bracketed folder is still allowed when no quarantine folder lies under its parent (for example a Next.js `app/[slug]`).

## Stalled-gate test

A throwaway copy of the plugin, loaded with `--plugin-dir`, had its Bash hook run `sleep 30;` before `launch_gate.py`, against the hook's 15-second timeout. Claude Code printed `timed out; blocking because onFailure is "block"`, and the command (an `echo`) never ran. This is the first live proof that `onFailure: "block"` makes a stalled gate block.

## Marketplace install (local folder)

- `/plugin marketplace add <checkout>` and `/plugin install stranger-danger@claude-code-stranger-danger` both succeeded.
- After a restart, `/stranger-danger:doctor`'s three live probes were refused by the installed copy's hooks: WebFetch to `127.0.0.1:9`, a Read under `~/.ssh`, and `npx --version`.
- The doctor ended with 20 pass, 3 warn and 1 fail. That's expected for a bare test profile: no `RULES.md`, no template deny or ask rules, and the sandbox off.
- A main-session request to search the web was handed to `stranger-danger:web-researcher`, which ran.
- With a marketplace added from a local folder, the hooks ran from the checkout path. Claude Code also wrote a copy to its plugin cache (`<profile>/plugins/cache/claude-code-stranger-danger/stranger-danger/0.1.0/`). Which folder `/stranger-danger:setup` resolves to wasn't checked.
- So with a marketplace added from a live local checkout, pulling or switching branches there changes the active gates without `/plugin update`.
